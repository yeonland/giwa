# 코드 규칙

코드를 새로 쓰거나 고칠 때 이 규칙을 따른다. 규칙이 바뀌면 이 문서부터 고친다.

## 1. 파일

| 파일 | 하는 일 |
|------|---------|
| `index.html` | 화면 전체: 마크업, `<style>`, `<script>` |
| `data.js` | 용어 카드 데이터 (`window.TERMS`) |
| `docs/` | 기획·규칙 문서 |

- 지금은 파일을 나누지 않는다. `index.html`이 300줄을 넘거나 Astro로 옮길 때 `css/`, `js/`로 나눈다.
- 빌드 도구·라이브러리 없이 HTML, CSS, JavaScript만 쓴다. 라이브러리가 필요하면(지도의 Leaflet 등) README "사용 기술"에 이유를 적고 넣는다.

## 2. HTML

- 의미에 맞는 태그를 쓴다: 머리글 `header`, 본문 `main`, 도해 `section`, 옆 영역 `aside`, 카드 `article`, 카드 항목 `dl/dt/dd`.
- 누를 수 있는 것은 키보드로도 누를 수 있어야 한다. `button`을 쓰고, SVG 부재처럼 `button`을 못 쓰면 `tabindex="0"` + `role="button"` + `aria-label`.
- 바뀌는 글(카드)은 `aria-live="polite"`.
- `lang` 속성은 화면 언어에 맞춘다 (`ko` / `en`).

## 3. CSS: BEM

이름은 `블록__요소--수정자`.

- **블록**: 혼자서 뜻이 있는 덩어리. `header`, `layout`, `plan`, `search`, `card`
- **요소**: 블록 안의 부분. 블록 이름 + `__` + 요소 이름. `card__title`, `plan__part`
- **수정자**: 모양·상태가 다른 경우. `--` + 이름. `plan__part--active`, `plan__shape--fill`
- 이름은 영어 소문자, 단어 사이는 `-` (`card__empty-text`).
- 요소 안의 요소도 블록 바로 아래로 쓴다: `card__list__item` ❌ → `card__item` ✅
- 선택자는 클래스 하나가 기본. 상태(`:hover`, `--active`)에 따라 자식을 바꿀 때만 `.plan__part--active .plan__shape`처럼 두 단계까지.
- CSS에서 `#id`와 태그 선택자는 쓰지 않는다. 예외: 맨 위 기본값(`*`, `body`, `button`, `input`).
- 색·간격 같은 값은 `:root` 변수로: `--paper`(바탕), `--ink`(글자), `--muted`(흐린 글자), `--tile`(강조, 기와색), `--water`(해자), `--line`(선).
- 휴대폰이 기본, 넓은 화면은 `@media (min-width:800px)`로 추가.

지금 쓰는 블록:

| 블록 | 요소 | 수정자 |
|------|------|--------|
| `header` | `__title` `__sub` `__lang` | |
| `layout` | | |
| `plan` (도해) | `__svg` `__part` `__hit` `__shape` `__label` `__hint` | `__part--active` `__shape--fill` |
| `search` | `__input` `__results` `__result` | |
| `card` | `__title` `__hanja` `__label` `__value` `__link` `__empty` | |

## 4. JavaScript

- **역할 나누기**: 클래스는 CSS만 쓴다. JS는 `id`(한 개뿐인 요소)와 `data-*` 속성으로 요소를 찾는다. 클래스 이름을 바꿔도 JS가 깨지지 않게 하려는 것.
  - `data-id`: 도해 부재가 가리키는 카드 id
  - `data-go`: 누르면 그 카드로 이동 (검색 결과, 관련 용어 링크)
  - `data-i18n`: 언어를 바꿀 때 `UI` 사전에서 글을 넣을 자리
  - 예외: 상태 표시는 BEM 수정자 클래스를 JS가 붙였다 뗀다 (`plan__part--active`).
- `const` 기본, 다시 넣는 값만 `let`. `var` 안 씀.
- 함수 이름은 동사로 시작하는 camelCase: `show`, `render`, `search`.
- 데이터에서 온 글을 `innerHTML`에 넣을 때는 반드시 `esc()`로 감싼다.
- 화면 글은 코드에 직접 쓰지 않고 `UI.ko` / `UI.en`에 넣는다.
- 이벤트는 `document`에 한 번 걸고 `closest()`로 대상을 찾는다 (카드 내용이 바뀌어도 다시 걸 필요 없음).
- 주석은 코드만 봐서는 모르는 "왜"만 한 줄로. 임시 방편은 `// shortcut: 한계, 언제 바꿀지` 형식.

## 5. 데이터 (`data.js`)

- 카드 필드는 기획서 8-4를 따른다: `id`, `entity`, `title`, `hanja`, `aliases`, `summary`, `howToSpot`, `tags`, `relations`, `dispute`, `sources`.
- 글이 있는 필드는 언어별로 나눈다: `{ "ko": "...", "en": "..." }`.
- `id`는 `엔티티-로마자`: `term-chi`, `site-dadaepo`.
- 로마자는 국어의 로마자 표기법을 따른다. 영어 제목은 `로마자 (설명)`: `Chi (projecting wall section)`.
- 관계는 `{ "type": "part-of", "target": "term-cheseong" }`. 없는 `target`은 페이지를 열 때 콘솔에 경고가 뜬다.
- 모든 카드에 `sources`를 적는다. 확인 전이면 `(확인 필요)`를 붙인다.
